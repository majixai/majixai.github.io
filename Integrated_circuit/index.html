Signal map

  • GPIO: route LEDs, button inputs, and optional buzzer feedback.
  • UART: serial debug and flash-time logging.
  • I2C/SPI: optional sensors for temperature, power, or fan control.
  • Wi-Fi: pool job fetch and result submission.
  • Timer: periodic status sampling and watchdog-safe housekeeping.

Workflow

  • Boot into a safe mode that confirms power, network, and storage readiness.
  • Load the miner profile and sync configuration with the ESP32 control plane.
  • Connect to the pool, decode incoming work, and prepare the nonce window.
  • Track hashes, shares, and rejects while keeping the UI responsive.
  • Surface metrics back to the repository dashboard via linked pages and reports.

400GHz protocol paradigm

On the circuit side, the 400GHz protocol paradigm is framed as a tiny, timing-critical control surface that favors deterministic edges, short verification spans, and clean fallback paths.

Signal roleCarry board intents, status words, and protocol counters between logic blocks.
Timing roleProvide a high-rate cadence for sync pulses, retries, and safe transitions.
Verification roleBind each burst to a route/hash fingerprint so hardware and repository state stay aligned.
Fallback roleAllow the board to degrade gracefully to UART, Wi-Fi, or local debug panels.

Clock discipline

Keep oscillator assumptions explicit and treat every protocol hop as time-bounded.

Frame shaping

Use compact headers with hashable metadata and tiny payloads for control exchange.

Error recovery

Move quickly to a known-safe mode if sync or verification drifts out of bounds.

Board telemetry

Expose link health, temperature, and current draw as first-class protocol outputs.

Hardware interpretation

  • Analog layer: a conceptual 400GHz lane for ultra-fast signaling semantics.
  • Digital layer: board state, acknowledgements, and route-verified payloads.
  • Control layer: power gating, LED status, and job lifecycle commands.
  • Audit layer: hash-manifest validation and router provenance checking.
  • Recovery layer: UART console, local storage, and Wi-Fi rescue paths.

Design rules

  • Never let the protocol outrun the ability to verify or log a frame.
  • Keep all unsafe state transitions behind a manual confirmation point.
  • Prefer visible diagnostics over opaque acceleration.
  • Mirror the same transport vocabulary on the ESP32 page for consistency.
  • Use router/hash integration as the canonical authority for newly added pages.
