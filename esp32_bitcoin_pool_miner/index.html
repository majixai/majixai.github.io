Hardware notes

  • ESP32 role: lightweight control plane for job polling, status LEDs, and pool connectivity.
  • Mining role: use the browser miner for simulation and the hardware page as a concept lab for real devices.
  • C bridge: keep firmware-facing logic in the C toolchain so performance-sensitive paths stay compact.
  • Routing: every new hardware page should stay linked from the router and hash modules.

Pool workflow

  • Load pool config and derive the worker identity.
  • Fetch a job, assemble the header, and precompute the midstate.
  • Iterate nonces until a share meets target difficulty.
  • Submit accepted shares and refresh the next job.
  • Record telemetry for shares, rejects, and reconnects.

400GHz protocol paradigm

The 400GHz protocol paradigm is treated here as a conceptual ultra-fast control plane that sits beside the mining workflow and favors tight timing, compact frames, and deterministic retries.

Carrier modelShort-range, high-frequency link semantics for lab-only coordination between miner, controller, and diagnostics surfaces.
Frame modelNanoframes with a minimal header, payload hints, and integrity tags that can be hashed for route validation.
Timing modelClock-aware exchange windows, periodic sync pulses, and fast timeout handling for noisy environments.
Fallback modelDrop to classic Wi-Fi or local console paths whenever the conceptual 400GHz channel is unavailable.

Session bootstrap

Use a small handshake that identifies the board, locks the control window, and announces the active job state.

Integrity lane

Hash the session metadata and compare route fingerprints before any mining command is accepted.

Retry lane

Apply bounded retries with backoff jitter so the protocol remains predictable under contention.

Telemetry lane

Carry live counters, temperature hints, and job acknowledgements as compact control echoes.

Protocol stack

  • Physical: conceptual 400GHz signaling with rigid timing and short burst semantics.
  • Link: acknowledge-only exchanges, burst windows, and deterministic congestion handling.
  • Session: board identity, miner profile, and job authorization tokens.
  • Application: mining job request, share submit, telemetry publish, and diagnostics sync.
  • Governance: route/hash checks, actions automation, and cross-directory provenance.

Safety and fallback rules

  • Prefer safe defaults when the 400GHz paradigm is only partially supported.
  • Clamp burst durations so debug and recovery paths always remain available.
  • Expose a manual override that drops the board back to classic web and serial interfaces.
  • Keep all control frames hash-checkable so the same integrity logic can audit the transport.
  • Mirror status to the Integrated_circuit page so hardware and transport stay aligned.
